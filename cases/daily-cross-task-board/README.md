# 横断タスクボードで今日と明日を組む

![Claude CodeがTodoist・予定・作業中のリポジトリを読んで、時刻の枠と配分の枠を持つボードに時間割と依頼文を書き、Todoistに完了・リスケを反映する。本人はボードを見て指示を出し、依頼文をほかの作業の会話に貼る概念図](cover.png)

Todoistのタスクと、学習・アプリ開発・執筆のリポジトリの作業を並べて、今日やることを決めたい。PCのClaude CodeがTodoist・Googleカレンダー・各リポジトリのコミットと計画・本人待ちのTODO.mdを読み、時刻つきの今日と明日のスケジュールを、データベース付きのアーティファクト（claude.ai上のWebページ）に書く。
**2026-10-21から使用（作業記録は18日分）。自動実行はしない。効果は未測定。**

**AI：** 入力の読み取り、優先順位に沿った割り付け、タスクを目的につなぐこと、ボードのデータベースの書き換えと検算、本人の指示によるTodoistへの反映、ほかの作業の会話へ渡す依頼文の作成、ログインが要るブラウザ作業。  
**人間：** 「リスト作って」「更新して」の依頼、目標の順位と時間帯と型の決定、チェックや声での完了・リスケの指示、AIに任せるかの判断、ブラウザのログイン。

再利用できる工夫：

- 夜と朝は時刻で区切り、毎日のルーティン（日記・筋トレ・資格の問題・読書）を型として入れる。開始が遅れた日は型ごと後ろへずらし、ルーティンは消さない。
- 平日の日中（仕事の合間）は時刻を決めず「配分の枠」にする。所要時間だけを出し、上から順にやる。入れるのは、声で答えるもの・スマホからAIに声で頼むもの・ChatGPT（Work）のブラウザ操作に任せるもの、の3種類だけ（本人の決定）。
- 「AIに任せる」タブで、AIに渡せるタスクを状態（すぐ進められる・作業中・結果を見る・材料待ち・別のAI・保留）で分け、次に何が要るかを1行で書く。
- AIに任せるタスクの詳細の先頭に、貼る先の会話と、そのまま貼れる依頼文をコピーのボタンつきで出す（本人「なんて頼めばいいのか分からない」）。依頼文の無いタスクは、差を集める道具が知らせる。
- 別のリポジトリの作業はタスク管理の会話で続けず、その作業用に新しく開く会話に貼る依頼文を作る。タスク管理の会話のまま記事を直すところまで続くのを、本人が嫌ったため。依頼文の作成はスキルにした。
- タスクにはなぜやるのか・どこから来たか・作業フォルダを書く。名前だけでは、どこで何をやるか分からないため。
- 本人待ちは各リポジトリのTODO.mdにだけ置き、ボードは読むだけ。古さは点検スクリプトとフックで機械に見つけさせる。点検がリポジトリ直下のTODO.mdの古さに、自分のTODO.mdを持つ取り組みのフォルダのコミットまで数え、毎回誤った警告を出していたので、数える範囲から外した。付箋の箱（Beads）は写しだったので古くなり、やめた（本人の判断）。
- 判断は本人、検算は機械。書き込みのあとに件数を数え直し、時刻の重なりとルーティンの抜けを確かめる。Todoistの完了・リスケ・削除は本人が指示したときだけ。
- 遅いときは、道具の時間とAIの待ちを分けて測る。ボードの更新に4分かかっていた（本人「時間かかりすぎ」）が、道具は13秒で、残りはAIが道具を17回順に呼んだ待ちだった。道具が要る物（今日と明日の枠、閉じた確認待ちの答え）をまとめて出し、書いたあとは全件を読み直さず、書き込みの結果の件数で検算する形にした。速くなったかはまだ測っていない。
- AIに任せて作業中のタスクは、相手のリポジトリの最後のコミット（日時と件名）を毎回見て、終わったのか止まったのかを見分ける。TODO.mdでは閉じたのにボードで未完の物も出す。
- Todoistの日付は実行日として扱う（本人「それは締め切りじゃなくて実行日ですからね」）。締め切りと前提条件は説明欄に書いてあるので、該当する行だけを毎回読む。
- 「日付」のタブで、今日これだけはやる物を★で先頭に置き、3回先送りした物を赤にする。空き時間（5・15・30分、スマホ）で絞り込める。
- 「目標」のタブで、細かいタスクの上に「目標 → 目的 → タスク」の3段を置く。目標は到達したい状態、目的はそのために何をするか・なぜそのタスク群が要るかのまとまり（例：目標「本を1冊書き上げる」→ 目的「毎週1章ずつ下書きを書く」→ タスク）。目の前の細かいタスクばかり片付けて、上位の目標に手がつかないのを防ぐため（本人の依頼）。目標に当てはまらない目的（家の用事など）は「目標の無い目的」として持ち、無理に目標を作らない。
- 目標のタブの上に、この2週間に済ませた数を目標ごとの棒で出し、上位の目標が0件なら赤にする。目的の行には「次のタスクが無い」「未着手」「N日動きなし」の印を出す。
- 目標の順位は本人が決め、画面は自動で並べ替えない。AIが仮に置いた順位は点線の枠で「仮」と分かるようにする。
- タスクは目的につなぎ、目標は目的からたどる（同じ情報を2か所に置かない）。ほかのタブのタスクにも「順位・目標 › 目的」のタグを出し、スケジュールにはその日の枠の分数を目標ごとに出す。分野ごとのタブ（家庭・学習・アプリ・執筆・雑務）は目的からたどれるので外し、タブを10個から6個に減らした。外して目に入りにくくなった本人待ちは「確認待ち」のタブに集めた。
- 目標のカードに、次の区切りを期間と「あと何日」で1行出す（例：目標「本を1冊書き上げる」の次の区切り「最初の3章を書き終える」）。
- 日付は、本当の締め切りと、本人が自分で置いた目安に分ける。目安は「目安」と出し、過ぎても赤にしない。始める条件があるタスクには日付を置かず「着手条件：〜」と出す（本人の依頼「期限と着手条件を区別し、未確定の案件に固定期限を設けない。」）。
- 目的の進み具合を、タスクを片付けた数ではなく、到達点（目的の中の区切り）の数で数えられるようにする。タスクを消化した数と、目標に近づいたかは別のため（本人の依頼）。
- タスクにしない細かい単位（例：章ごとの原稿）は、目的の下に「書いた・7割・未着手」のような状態つきの一覧で出し、済んだ物だけを数える。12件までの短い一覧は最初から開く。一覧は本人が言った状態と正本のリポジトリの写しで、確かめていない物を済みにしない。
- 1つのタスクが2つの目的に効くときは、両方の目的から参照する（例：「章立てを1ページにまとめる」は「毎週1章ずつ下書きを書く」と「読み手に見せる準備をする」の両方に出る）。
