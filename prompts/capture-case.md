# 別チャットからも使うケース記録指示

対象のリポジトリは `n-yoshida-dev/ai-use-cases` です。作業開始時に最新mainの `AGENTS.md` を全文読み、そこにある読み取り順・対象範囲・図の規則を守ってください。GitHubを直接操作するときも、ローカルで編集するときも同じです。読めなければ、推測で書き込まずに不足を報告してください。

1. 参照できる会話・成果物を確認し、AGENTS.md「登録対象」の工夫（ChatGPT・Claude.aiのチャット／Work／スケジュール、Claude Codeのルーティン、Claude Codeの会話で続けている運用）に該当するかを判定する。Claude Code製の独立アプリ・プロジェクト紹介は除外する。
2. 関連する既存ケースを読み、重複していればその既存ケースを更新する。本人の判断、AIの作業、実行状況、成果と未確認点を区別する。
3. 公開可能な内容だけを短いREADMEとmetaへ整理する。platforms・modesには確認できた実績だけを記録し、会話全文を保存しない。
4. 図を描ける環境（Python と `scripts/figkit.py` を動かせる）なら、日本語の絵中心の `cover.png` を `figure.py` で作る。2枚目が要るなら手順の流れ図の型で `flow.png` を作り、編集元を残す。描けなければ図を作らず、描く内容を meta.yaml の `figure_todo` に書く（AGENTS.md「見せ方と図」）。
5. 関連するsystemsの全体構成を確認し、連携が変わる場合は図・README・metaと相互リンクも更新する。トップREADMEの画像一覧と、ケースREADMEの先頭の図を更新する。説明図（`flow.png`）は折りたたみに置く。紹介資料に載せるなら meta.yaml に `deck` も書く（AGENTS.md「紹介資料に載せる中身（deck）」）。図・本文・meta・リンクを検証する。
6. 書き込み直前に最新mainを再確認し、他者の更新を残したまま、まとまったコミットで反映する。反映した変更と未確認点を短く報告する。

この指示はケースを記録するためのものです。元の作業の追加実行、定期タスク作成、記事投稿はこの依頼からは行いません。
